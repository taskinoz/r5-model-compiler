`r5studiomdl` 1.0.2 identifies two sequence fields that earlier releases kept as stored without a known meaning. Compiled output is unchanged.

**The 0xC8/0xCC sequence table is a list of weight ramps**
- Each 24-byte record holds a weight, a bone (-1 for the whole sequence) and four cycle points: start, peak, tail and end.
- R5R's sequence blend routine scales the sequence's (or that bone's) weight from 1 down to the record's weight between start and peak, holds it until tail, and returns it to 1 by end.
- Retail uses them on 185 menu and banner sequences: banner intros fade in and out, menu poses hold 0.1.
- The QC option is now `weightramp`; `unk_cc` is still accepted, and `decompile54.py` writes the new name.
- In game, a ramp changed neither a prop's played sequence nor its autolayers, so its effect is in menu and banner blending, which the test harness does not drive.

**Flag 0x40 is not used by R5R**
- No code in r5apex.exe tests the bit on a sequence's or clip's flags.
- The B3 Wingman's execution clip, imported with and without the flag, posed identically over 90 samples (within 0.0022 in of retail), with the same duration and root motion.
- It is most likely a marker from Respawn's tools. The compiler keeps it so imports still match retail.

**Test tools**
- `build_r5r_import_test.py --case b3wing [--clear-flag40]` builds the flag test.
- `build_r5r_delta_test.py` adds the weight-ramp cases.
